  • Every run each worker sends the same prompt (540 support tickets, answer 70 of them in a fixed format) to the same deployment; only service_tier differs. A per-request nonce at the start of the prompt prevents prompt caching.
  • TTFT = first content token, TTLT = end of stream, tok/s = output tokens ÷ (TTLT − TTFT).
  • VNet-integrated Container Apps, private endpoints, one managed identity (Entra ID), no keys.
stream = client.chat.completions.create(
    model=deployment, messages=messages,    # ≈50k input tokens
    service_tier="priority",          # "flex" | "default" (Standard)
    reasoning_effort="none", max_completion_tokens=8000,
    stream=True, stream_options={"include_usage": True})

Same code for all tiers. Flex: long timeout + retry on 429. Priority: check the returned service_tier ("default" = downgraded, billed as Standard).

3. Billing

One deployment and quota for all tiers; Cost Management charges them on separate meters: Standard on regular meters, Priority on PP meters (2×), Flex on Fl meters (0.5×). Rejected Flex requests (429) are not billed. Evidence: report-phase1.html, section 9.
